The repository deploys to [Vercel](https://vercel.com) as it is. Vercel builds the static site from `web/` and runs the Laravel API as one PHP serverless function at `/api`, using the community [`vercel-php`](https://github.com/vercel-community/php) runtime. The settings live in `vercel.json` at the repository root, so you don't have to change any build settings in the Vercel dashboard.

## Deploy with one click

Use [**Deploy with Vercel**](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fiairu%2Ffindacat-neo&project-name=findacat&repository-name=findacat&env=APP_NAME%2CDISABLE_SIGNUPS%2CMAIL_MAILER&envDefaults=%7B%22APP_NAME%22%3A%22Find%20A%20Cat%22%2C%22DISABLE_SIGNUPS%22%3A%22false%22%2C%22MAIL_MAILER%22%3A%22log%22%7D&envDescription=The%20defaults%20work%20as%20they%20are%3B%20APP_KEY%20and%20the%20setup%20token%20are%20generated%20by%20the%20build.%20For%20real%20email%20set%20MAIL_MAILER%20to%20smtp%20later%20and%20add%20MAIL_HOST%2C%20MAIL_PORT%2C%20MAIL_USERNAME%2C%20MAIL_PASSWORD%20and%20MAIL_FROM_ADDRESS.&envLink=https%3A%2F%2Fgithub.com%2Fiairu%2Ffindacat-neo%2Fblob%2Fmain%2Fweb%2Fsrc%2Fcontent%2Fdocs%2Fen%2Fadmin%2Fvercel.mdx%23environment-variables&products=%5B%7B%22type%22%3A%22integration%22%2C%22integrationSlug%22%3A%22neon%22%2C%22productSlug%22%3A%22neon%22%2C%22protocol%22%3A%22storage%22%7D%5D) (the same button is in the repository's `README.md`). It:

1. copies the repository to your GitHub, GitLab or Bitbucket account,
2. asks for `APP_NAME`, `DISABLE_SIGNUPS` and `MAIL_MAILER`, already filled in with working defaults (`Find A Cat`, `false`, `log`),
3. creates a **Neon Postgres** database for the project, preselected (confirm the Neon terms and the free plan when asked),
4. builds and deploys.

Nothing else is needed for the first deployment. The build runs the database migrations and generates the encryption key (`APP_KEY`) and a setup token itself. Emails go to the function log until you add SMTP settings. Continue with [Create the first administrator](#create-the-first-administrator).

## Import an existing repository

If you import the repository through **Add New → Project** instead, Vercel cannot add the database for you:

1. Vercel offers the repository root (`./`, detected as Astro through the root `package.json`) and `web`. Keep `./`: `vercel.json` sets the build for both the site and the API and overrides the preset. Optionally paste `.env.example` into **Environment Variables**, then deploy.
2. In the project open **Storage → Create Database → Neon** and connect it to all environments. This adds `DATABASE_URL` / `POSTGRES_URL`, which the API picks up automatically.
3. Open **Deployments**, and **Redeploy** the latest deployment so the build can reach the database.

To use another database, set `DB_URL` yourself, for example `mysql://user:password@host:3306/findacat` or `postgres://user:password@host:5432/findacat?sslmode=require`.

## What the build does

The root `composer.json` installs the API and then runs `php artisan vercel:build`, which:

- runs the database migrations, so every deployment brings the database up to date;
- creates `APP_KEY` and a setup token on the first build and keeps them in the `app_secrets` table, so every later deployment, including previews on a Neon branch, uses the same values;
- prints the setup link in the build log while no administrator exists.

If the build cannot reach a database, it says so in the log and the site deploys without a working API. Connect a database and redeploy.

## Create the first administrator

Open **Deployments**, select the deployment and expand **Build Logs**. Near the end of the PHP step there is a line like:

```
Create the first administrator at https://your-project.vercel.app/api/install?token=…
```

Open that link, enter a name, email and password (12 characters or more) and press **Run setup**. The setup page stops working as soon as an administrator exists, so there is nothing to clean up afterwards. Build logs are only visible to members of the Vercel project.

## Environment variables

None are required. `.env.example` at the repository root lists them; the **Environment Variables** page accepts it pasted in as a whole.

| Variable | Value |
| --- | --- |
| `MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS` | Your SMTP account, with `MAIL_MAILER=smtp`. Without them, confirmation and password-reset emails are only written to the function log. |
| `APP_NAME` | `Find A Cat`, or the name to show in emails. |
| `APP_URL` | Only for a custom domain: `https://your-domain.example`. |
| `DISABLE_SIGNUPS` | `true` or `1` closes registration: the sign-up page shows a notice instead of the form. Existing accounts keep working. |
| `DB_URL` | Only when the database was not added through the Marketplace. |
| `APP_KEY` | Generated. Set it only to keep the key of an earlier installation, for example `echo "base64:$(openssl rand -base64 32)"`. |
| `INSTALL_TOKEN` | Generated. If you set your own, the setup page also runs pending migrations after an administrator exists; remove it when you are done. |

Everything else has a Vercel default in `api/bootstrap/vercel.php`: production mode, logs to the Vercel function log, sessions and cache in the database, secure cookies, trusted proxy headers, and a writable storage folder under `/tmp`. Any variable you set yourself takes precedence. Variables apply to deployments built after you change them, so redeploy after editing.

## Preview deployments

With preview branching turned on in the Neon integration settings, each preview deployment gets its own database branch copied from the main database, so its migrations and test data stay out of production. Otherwise, or with another database, give **Preview** its own `DB_URL`: preview builds would migrate the production database.

## Upgrade

Push to the production branch. Vercel builds and deploys it, and the build applies any new migrations.

## Limits

- **Uploads:** Vercel limits a request body to 4.5 MB. Split larger CSV backups, or import them from your own computer with `php artisan legacy:import --breeds=… --ems=… --cats=…` and `DB_URL` pointing at the same database.
- **First request:** after a quiet period the function starts cold, which takes a second or two.
- **Run time:** `vercel.json` allows 60 seconds per request, which is enough for pedigree and inbreeding calculations and for exports of a large database.

## Troubleshooting

- **The build log says "No database reachable":** connect a database as described above and redeploy.
- **A migration fails with `current transaction is aborted`:** the build is migrating through a connection pooler. With Neon it uses the direct connection (`DATABASE_URL_UNPOOLED`) automatically; if you set `DB_URL` yourself, point it at the direct host (without `-pooler`).
- **The build fails in the PHP step:** open the build log. A migration error stops the deployment so that a half-migrated database never goes live.
- **`/api/health` works but other pages return "Server Error":** look in **Logs** for the function. A missing `cache` or `sessions` table or `No application encryption key` means the build ran without a database; redeploy.
- **Everyone was signed out:** the key lives in the `app_secrets` table, so a new or reset database gets a new key. Set `APP_KEY` to keep one across databases.
- **Emails link to the `vercel.app` address instead of your domain:** set `APP_URL` to your domain and redeploy.
